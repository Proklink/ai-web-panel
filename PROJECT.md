# Webpanel — контекст проекта

> Рабочий файл для продолжения разработки (для Claude и для владельца). Обновлять при каждой остановке.
> Последнее обновление: 2026-11-12 (вторая сессия: mTLS развёрнут и протестирован).

## Цель

Личное (некоммерческое) веб-приложение на этом сервере для диалогов с Claude Code из браузера с разных
устройств. «Пользователи» — это устройства владельца. Каждый диалог — отдельная сессия Claude в tmux,
которая живёт, пока её не закроют.

## Требования (от владельца)

1. Веб-сервер здесь, бэкенд на Python, фронт на React.
2. Пользователи с логином/паролем, хранение в PostgreSQL (SQLite допустим, если Postgres тяжёл — оставили
   Postgres, урезанный профиль ~40 МБ).
3. Незалогиненный — нет доступа к чатам и истории.
4. Пользователь не видит чужие диалоги (админ тоже не видит содержимое — только управляет сессиями).
5. Пользователи условные — устройства владельца.
6. Чаты запускаются в tmux и живут до закрытия. Список диалогов слева, название — первая строка.
7. Можно завести нового пользователя (админ создаёт сам или выдаёт код приглашения).
8. Первый пользователь — админ: удаляет пользователей, выбирает проект из `workspace/` для чатов
   (выдаёт пользователям доступ к проектам).
9. Без проекта — контекст хранится в личной папке диалога.
10. Удаление диалога стирает все его данные (включая транскрипт Claude в `~/.claude`).
11. Вкладка потребления ресурсов сервера.
12. Безопасность.
13. Права: админ — всё, но деструктивное с ОС и вне workspace — с подтверждением в UI. Остальные по
    умолчанию — только чат; права (web/read/write/bash) выдаёт админ.
14. Не больше 2 активных сессий на пользователя по умолчанию, админ меняет.
15. Всегда оставлять ≥1 ГБ RAM: при нехватке выгружать сессии на диск (сжато), показывать это на фронте;
    при возврате в RAM проверять, хватит ли памяти; ошибки в рантайме обрабатывать.
16. Экстренно завершать/удалять чаты обычных пользователей, если серверу грозит зависание —
    с отображением, что произошло.
17. Доступ из интернета по HTTPS (домена пока нет → сертификат на IP).
18. Защита 443 от ботов: **mTLS** (сертификаты устройств). Выпуск и скачивание сертификата — во вкладке
    «Управление». Вход без сертификата — только для админа и только временно.
19. Документация: этот файл + инструкция по запуску + единый скрипт с `help` и примерами.

## Архитектура

```
браузер ──HTTPS(mTLS)──> Caddy :443 ──> uvicorn/FastAPI 127.0.0.1:8100 ──> PostgreSQL (localhost)
                                              │  unix-сокет
                                              ▼
                       tmux -L webpanel: сессия wp-<chat_id> → runner.py → claude -p (stream-json)
                                                                    │ PreToolUse-хук (hook.py)
                                                                    └──> POST /internal/hook → policy.decide()
```

- `backend/runner.py` — живёт в tmux, держит `claude -p --input-format/--output-format stream-json`,
  пишет события в `/var/lib/webpanel/chats/<id>/events.jsonl`, принимает команды по `runner.sock`.
  Переживает перезапуск веб-сервера (systemd `KillMode=process`).
- `backend/hook.py` — PreToolUse-хук: спрашивает `/internal/hook`, при недоступности — запрет.
- `backend/app/policy.py` — права на инструменты; список опасных команд (regex).
- `backend/app/chats.py` — менеджер сессий: запуск/выгрузка (gzip событий + tar.gz транскрипта Claude),
  возобновление `--resume`, экстренное завершение, удаление со стиранием, подтверждения, защита памяти
  (цикл 3 с: ниже резерва — выгрузка простаивающих, ниже критического порога — SIGKILL занятых чатов
  обычных пользователей; всё пишется в `incidents` и в чат).
- `backend/app/auth.py` — argon2id, серверные сессии (cookie HttpOnly/Secure/SameSite=Strict), CSRF
  (заголовок X-Requested-With + Origin), rate limit входа, проверка устройства (mTLS).
- `backend/app/certs.py` — свой CA (`/etc/webpanel/client-ca`), выпуск `.p12` (ключ не хранится).
- `backend/app/caddyconf.py` — генерация Caddyfile: режим `strict` (require_and_verify) или `window`
  (verify_if_given, только админ без сертификата, до времени из `/etc/webpanel/nocert-until`).
- `backend/app/main.py` — REST + WebSocket `/api/ws`, раздача собранного фронта.
- `frontend/` — Vite + React + TS: Login, App (сайдбар, вкладки), ChatView, Resources, Admin, Access, Settings.
- `webpanel.sh` — установка и обслуживание (`./webpanel.sh help`).
- Обычные пользователи запускаются с `--restricted --strict-mcp-config --tools <по правам>` + хук.
  Админ — полный набор инструментов + хук (опасное → подтверждение в UI).

## На чём остановились

**Всё из плана развёрнуто и проверено.** Система сброшена в чистое состояние для первого входа владельца:
пользователей нет, сертификатов нет, CA пересоздан, новый код настройки (`./webpanel.sh setup-code`),
окно входа без сертификата открыто на 60 минут (потом — только с сертификатом; продлить —
`sudo ./webpanel.sh open-window 30`).

Проверено во второй сессии (тестовые скрипты были во временной папке, удалены вместе с данными):
- mTLS через настоящий Caddy, 23 проверки: окно → создание админа без сертификата; без сертификата
  продлить окно нельзя; выпуск .p12 (читается openssl и cryptography); сессия без сертификата
  закрепляется за сертификатом; регистрация устройства по инвайту + сертификату; не-админ без
  сертификата — 403; чужой сертификат — 403; подделанный X-Client-Cert-Fp игнорируется; украденная
  cookie с другого устройства — 401; strict без сертификата — обрыв TLS (certificate required);
  отзыв — 403 сразу; свой текущий сертификат отозвать нельзя; скачивание CA сервера.
- После закрытия окна сессии без сертификата удаляются. WebSocket через Caddy с сертификатом работает,
  чужой Origin отклоняется.
- Подтверждение опасной команды у админа: `rm -rf` → карточка → до разрешения не выполнено →
  «Разрешить» → выполнено, решение записано в историю.
- fail2ban: jail `webpanel` ловит `LOGIN_FAIL` (свой IP сервера игнорируется правилом ignoreself),
  бан через nftables работает.
- UI в headless Chromium (Playwright, с клиентским сертификатом): вход, создание чата, стриминг,
  карточки инструментов, markdown, вкладки «Ресурсы» и «Управление», мобильная ширина 390px
  (без горизонтальной прокрутки, светлая тема), ошибок в консоли нет. Исправлены мобильные огрехи
  (вкладка «Профиль» перенесена в меню по нажатию на имя, компактная шапка чата).

Найдено и исправлено: при client_auth Caddy отвечает 421 на запросы по IP (нет SNI) — добавлен
`servers { strict_sni_host insecure_off }` для режима IP.

## Известные проблемы и риски

- Чаты админа наследуют MCP-серверы/коннекторы пользовательского конфига Claude (claude.ai Docs и т.п.)
  и их инструкции — Claude в веб-чате может упоминать их. Обычных пользователей это не касается
  (`--strict-mcp-config`). При желании — `--strict-mcp-config` и для админа.
- Для IP-режима выключен `strict_sni_host` (иначе 421). Безопасно, пока на Caddy один сайт.

- Право `bash` для обычного пользователя даёт выполнение от root: regex-фильтр не является изоляцией.
- Список опасных команд (policy.py) эвристический — возможны ложные срабатывания и обходы
  (например, через `python -c`). Для админа это лишь «предохранитель».
- После `--resume` Claude выдаёт новый session_id — учтено, но стоит перепроверить при обновлениях CLI.
- Caddy из apt — 2.6.2 (старый). IP-сертификаты Let's Encrypt не поддерживает.
- Пароль для .p12 3DES/SHA1 — слабое шифрование контейнера (ради совместимости с iOS); файл после
  установки нужно удалять.
- `pkill -f`/`pgrep -f` с шаблоном, который встречается в той же команде, убивает собственную оболочку —
  при отладке использовать шаблоны вида `uvicorn ap[p].main` и не держать в одной команде строку-совпадение.
- tmux-сервер стартует из службы: `systemctl stop webpanel` не закрывает диалоги (`stop --all` — закрывает).

## Как продолжить

```bash
cd /root/workspace/webpanel
./webpanel.sh help                 # все команды с примерами
sudo ./webpanel.sh install         # развернуть текущий код (включая mTLS)
./webpanel.sh status               # службы + открытые диалоги
./webpanel.sh logs -f              # журнал
./webpanel.sh setup-code           # код для создания админа
sudo ./webpanel.sh open-window 30  # временно пустить админа без сертификата
```

Разработка: `sudo ./webpanel.sh stop && sudo ./webpanel.sh dev` (бэкенд с автоперезагрузкой) и
`cd frontend && npm run dev` (Vite с прокси на 8100). Без сертификата локально — нужно открытое окно.

Секреты: `/etc/webpanel/webpanel.env` (600). Данные: `/var/lib/webpanel/chats/`. БД: `webpanel`
(`sudo -u postgres psql webpanel`).
